# FanPass Main App Audit - 2026-07-11

## Summary

The main FanPass app builds successfully and its core staging paths are materially implemented: Privy-backed authentication, Keychain session persistence, Stripe test-mode authorization, sponsored USDC checkout, backend ticket ownership, resale listing/cancellation, signed QR generation, remote ticket status refresh, and chain-proof display.

At audit time it was not ready to be treated as a public beta. The highest observed risk was product truth: live backend state and mock/demo state shared active user flows. This review is code-backed; no Instruments trace or before/after runtime metrics were collected.

## Resolution Update - 2026-07-12

The productization pass addressed the audit items below without adding the deferred iOS test target:

- **Dependency gate resolved:** Nest was upgraded to `11.1.28`; patched Multer/Engine.IO/`ws` versions are locked. The Node 22 production audit is clean, the fail-closed advisory gate reports no release blocker, all 19 API suites pass with 115 tests, and Render deploy `dep-d996v2mcjfls73fqlq5g` is live.
- **Active mock transactions removed:** API event, wallet, Market, checkout, and Account routes no longer append mock entities or report local-only success. Fake limit orders, fake resale review, fake checkout tickets/proof history, fake Apple Pay/Wallet completion, and unreachable account mutations were removed or hidden from the active product path. Preview fixtures remain in preview/mock modules.
- **Friend listing purchase fixed:** V4 Market enables checkout from the remote lowest SELL ask instead of requiring a buyer-local `ResaleListing`. It sends `RESALE_ONLY`; primary checkout sends `PRIMARY_ONLY`. Cross-device listing management reloads the real SELL order and price.
- **Concurrent purchase hardened:** Prisma settlement now rolls back all BUY/SELL/ticket claims if any claim loses the race. The losing resale-only buyer is rejected and its payment authorization is compensated; it never receives primary inventory or another buyer's trade.
- **Failure states improved:** Wallet/event/order failures propagate to explicit loading/error UI. Signed-out Home no longer calls a protected wallet endpoint. A centralized one-time 401 refresh policy remains open.
- **Refresh work completed in part:** Market uses the existing Socket.IO feed with HTTP fallback; ticket detail polls only while active at 2-second/5-second intervals and stops at terminal state. The broad revision loop was reduced from 5 to 15 seconds but still needs full domain separation.
- **QR rendering fixed:** the bitmap is cached by credential and is no longer regenerated by each countdown update.
- **Legacy target reduced:** the main app target excludes the old shell and legacy feature trees. Both FanPass and FanPassOps compile. Large active files still need splitting.
- **iOS tests deferred by owner:** the owner stated the audit's second action had already been tested and asked work to continue without creating a new test target. This remains a release-risk acceptance, not proof of automated lifecycle coverage.

Simulator verification used the deployed staging orderbook. The real `evt_aurora_vip` ask at HK$1,235 appeared as `Live`, enabled `Buy lowest resale`, and routed to Secure Resale Checkout at the same amount. No order or payment was submitted because the simulator was signed out; signed-in two-account Stripe settlement remains the next manual product test.

## Findings

### P0 - Production dependency security gate currently fails

The live Node 22 production audit reports six high-severity findings and no critical findings. They are the Nest Express upload chain (`@nestjs/platform-express` -> `multer`) and the Socket.IO transport chain (`engine.io`, `engine.io-client`, `socket.io-adapter` -> `ws`). The reported issues are upload denial of service and WebSocket memory-exhaustion denial of service; npm reports a fix path for each finding.

`npm run security:dependency-advisories` fails because its allowlist still expects the older Next/PostCSS state. This is desired fail-closed behavior, but it means the API dependency baseline is not currently releasable.

Fix: perform a focused Nest/Socket.IO dependency update, update the advisory policy only after a clean audit, run API typecheck/build/tests plus orderbook socket, payment, auth, and verification regressions, then deploy and smoke Render staging. Do not use a force upgrade without that regression set.

### P0 - Active user flows still present mock actions as real operations

- `FanPassV4APIEventService.featuredEvents` appends mock review events after the live API catalog (`FanPassV4APIDataProvider.swift:39-46`).
- Market Sell selects a mock ticket instead of loading the signed-in user's eligible backend tickets (`FanPassV4MarketView.swift:240-242`).
- Market listings merge backend-local overlays with mock listings (`FanPassV4MarketView.swift:260-274`).
- Limit order submission only changes local confirmation text (`FanPassV4MarketView.swift:1364-1366`), and the resale review confirmation is local state only (`FanPassV4MarketView.swift:1383-1414`).
- Account contains hard-coded orders and local-only profile, export, settings, and support success states (`FanPassV4ProfileView.swift:240-250`, `626-667`). It also labels Card as ready and shows Apple Pay even though readiness depends on runtime config and Apple Pay is not implemented (`FanPassV4ProfileView.swift:362-367`).

Impact: a user can be told that an order, account change, support request, or market action succeeded when no server-side state changed.

Fix: keep fixtures in previews or an explicit DEBUG-only demo repository. Beta/Release screens must render only backend-backed entities, use real mutation endpoints, or show an honest unavailable state.

### P0 - There are no iOS test targets

`project.yml` defines only `FanPass` and `FanPassOps`; `xcodebuild -list` confirms there are no unit-test or UI-test targets.

Impact: auth restoration, Stripe result handling, ticket listing/QR pause, remote `REDEEMED` reconciliation, and simultaneous state changes can regress without a build failure.

Fix: add a `FanPassTests` target first, with injected API/session repositories and deterministic tests for the five critical lifecycle paths. Add a small UI smoke target after the state layer is testable.

### P1 - API failures are converted into valid-looking empty state

`walletTickets` catches every error and returns `[]`; exact ticket lookup catches every error and returns `nil` (`FanPassV4APIDataProvider.swift:109-141`). The UI therefore cannot distinguish an empty wallet from expired auth, Render cold start, timeout, decoding failure, or server error. This matches the previously observed multi-device symptom where the account stayed signed in but information disappeared.

`FanPassAPIClient.performPost` also uses `EmptyResponse() as! T` for empty bodies (`FanPassAPIClient.swift:367-385`), which can crash if an endpoint returns an unexpected empty success response.

Fix: return typed loading/success/empty/failure states, handle 401 with one session refresh path, define request timeouts, and remove the force cast.

### P1 - Realtime refresh is too broad and too frequent

`FanPassBackendContext` increments a global revision every five seconds (`FanPassBackendContext.swift:95-110`, `289-290`). Tickets and Market key their tasks from that revision (`FanPassV4TicketsView.swift:30-33`, `FanPassV4MarketView.swift:85-87`). Ticket Detail separately polls every second (`FanPassV4TicketsView.swift:637-645`), and each exact-ticket refresh also fetches the complete event catalog for mapping (`FanPassV4APIDataProvider.swift:130-138`).

This keeps USED state responsive, but it creates unnecessary network, CPU, and battery load. The existing Socket.IO orderbook client is not used by the V4 Market screen.

Fix: split refresh signals by domain. Use the existing orderbook socket for Market, add a ticket-status event or a lightweight status endpoint, and retain adaptive polling only while an active QR is visible. Pause polling when the app is inactive and back off after errors.

### P1 - The QR bitmap is regenerated during countdown updates

`FanPassEntryQRCodeImage` creates a `CIContext` and QR filter and calls `makeImage()` from `body` (`FanPassV4TicketsView.swift:877-910`). The parent countdown mutates every second, so the same credential can be rendered repeatedly.

Fix: generate/cache the bitmap when the credential string changes. Keep the countdown in a separate leaf view so it does not invalidate the QR subtree.

### P2 - The main target compiles a second, unused app architecture

The FanPass target compiles 50 Swift source units. About 2,719 lines belong to the old `AppShellView`/`AppState` and legacy Auth, Events, Marketplace, Tickets, Fan Access, Profile, Scanner, and orderbook realtime surfaces. `FanPassApp` launches only `FanPassV4AppShellView`, so the legacy shell is not reachable from the current product path.

The largest active files are also oversized: Market 1,721 lines, Profile 1,365, shared components 1,355, and Tickets 917. This increases build cost and makes state ownership harder to reason about.

Fix: first decide whether the realtime client will be reused by V4. Then remove/exclude the dead legacy shell and split active features by screen, state model, repository, and reusable leaf components. Do this after lifecycle tests exist.

## What Is Already Solid

- Persistable sessions use Keychain with device-only accessibility; the local review token is not persisted.
- Checkout requires authentication, a fan-capable role, a bearer session, live API state, a backend-backed catalog item, and Stripe public config.
- Ticket detail resolves exact ticket status from the backend before using pending local state.
- Backend redemption remains authoritative and atomic; the iOS USED overlay follows backend `REDEEMED` state.
- The current Debug simulator build succeeds without code-signing.

## Recommended Execution Order

1. Resolve the six high production dependency advisories, pass the security gate, deploy the verified dependency update, and smoke staging.
2. Add iOS test targets and repository seams for auth, tickets, market, and checkout.
3. Remove mock transactional behavior from Beta/Release; make Market Sell use owned eligible tickets and make limit/resale actions call real APIs.
4. Introduce typed load/error state and a single 401/session refresh policy.
5. Replace global polling with domain-scoped realtime/adaptive refresh and cache QR images by credential.
6. Remove the unused legacy iOS shell, split the four oversized active files, then run physical-device regression QA.

- Multi-device login and remote ticket/listing state propagation.
